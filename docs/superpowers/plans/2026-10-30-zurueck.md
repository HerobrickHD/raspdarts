# Zurück (Strg+Z) im Viewer – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jede Änderung am aktuellen Profil im Viewer lässt sich mit „Zurück“/Strg+Z zurücknehmen und mit „Wiederholen“/Strg+Y wiederherstellen.

**Architecture:** Ein reines Modul `history.js` hält die Schritte (Stand vorher/nachher, Zusammenfassen nach Schlüssel und Zeit). Ein kleines Modul `undo.js` verbindet es mit dem Viewer: Es nimmt Schritte aus Editor und Leiste auf und stellt beim Zurück einen Stand her – lokal über `applyLocalProfile`, an den Pi über `sync.queue` wie jede andere Änderung. `app.js` verdrahtet, `settings-panel.js` bekommt zwei Knöpfe im Kopf.

**Tech Stack:** Vanilla-JS-Module im Browser (`server/public/js`), Vitest (`server/test`).

**Spec:** `docs/superpowers/specs/2026-10-30-zurueck-und-navigation-design.md` (Teil 1)

## Global Constraints

- Gilt für: Lage auf der Bühne, Inhalte der Leiste, Format, Name, Zurücksetzen. Nicht: Profil wechseln/anlegen/löschen, Vorschau-Spielerzahl, Kästen auf/zu.
- Strg+Z = Zurück; Strg+Y und Strg+Umschalt+Z = Wiederholen; nur bei offener Leiste; nicht im Textfeld, nicht bei offenem Dialog.
- Reihen (Tasten, Mausrad) mit < **1 s** Abstand und demselben ausgewählten Ding = ein Schritt; Ziehen = ein Schritt.
- Höchstens **100** Schritte.
- Verlauf nur im Speicher des Geräts; leer bei Wechsel des aktiven Profils; bleibt beim Schließen der Leiste.
- Knöpfe „Zurück“/„Wiederholen“ im Kopf der Leiste, gesperrt statt versteckt, `title` „Zurück (Strg+Z)“ und „Wiederholen (Strg+Y)“.
- Kommentare und Texte deutsch wie im Code (Kommentare ohne Umlaute, sichtbare Texte mit).
- Teil 1 wird allein ausgeliefert: nur `server/package.json` auf **2.2.0**, keine Extension-Änderung (meine Entscheidung: die Extension bleibt 2.1.1, bis Teil 2 beide auf 2.3.0 bringt).

## Review Focus

- Deutsche Tastatur (QWERTZ): Strg+Z muss die Taste mit „Z“ treffen → `event.key` (nicht `event.code`, das wäre dort `KeyY`); Groß-Z bei Umschalt/Feststelltaste. Test in Task 4 über eine reine Funktion `undoKey(event)`.
- Schnell weiter drücken nach einem Zurück: die nächste Pfeiltaste darf nicht in den zurückgenommenen Schritt hineinlaufen. Test in Task 1.
- Zurücksetzen schlägt fehl (Pi aus): kein Schritt. Test in Task 2 nicht nötig, weil der Schritt erst in `.then` aufgenommen wird; im Code von Task 4 so lösen.
- Echo vom Pi mit derselben Profil-ID darf den Verlauf nicht leeren, nur eine andere ID. Bedingung in Task 3.
- Strg+Z im Namens-Dialog: der Browser nimmt das Tippen zurück, nicht unser Verlauf. Test in Task 4 (`undoKey` mit Ziel im Textfeld → null).

### Task 2: `undo.js` – Verlauf mit dem Viewer verbinden

**Files:**
- Create: `server/public/js/undo.js`
- Test: `server/test/undo.test.js`

**Interfaces:**
- Consumes: Task 1 (`createHistory`, `snapshotOf`, `snapshotPatch`)
- Produces: `createUndo({ getProfile, applyLocalProfile, sync, getEditing, onChange, history = createHistory() }) → { record(beforeProfile, afterProfile, key = null), undo(), redo(), canUndo(), canRedo(), clear() }`
  - `record`: speichert Schnappschüsse, ruft `onChange()`.
  - `undo`/`redo`: Stand aus dem Verlauf; `patch = snapshotPatch(snapshotOf(getProfile()), target)`; leer → nichts; sonst `applyLocalProfile({ ...profile, ...target })`, `sync.queue(profile.id, { ...patch, editing: getEditing() })`, `sync.flush()`, `onChange()`. Ohne Profil nichts.
  - `clear`: leert, ruft `onChange()`.

- [ ] **Step 1: Tests** mit Fake-`sync` (`{ queue: vi.fn(), flush: vi.fn() }`) und einem `profile`, das `applyLocalProfile` ersetzt:
  - „undo stellt den alten Stand her und schickt nur die geaenderten Felder“: record(p, p mit anderem `format`) → undo → `applyLocalProfile` mit altem `format`, `sync.queue(p.id, { format: "fenster", editing: … })`, `flush` aufgerufen, Profil-`id` unverändert.
  - „redo stellt den neuen Stand her“.
  - „Zuruecksetzen zurueck: name/format/content/layout in einem PUT“ – record(p, ganz anderes Profil) → undo → queue-Patch hat genau die abweichenden Schlüssel.
  - „ohne Schritt: nichts gesendet“.
  - „onChange nach record, undo und clear“.
- [ ] **Step 2:** `npx vitest run test/undo.test.js` → FAIL
- [ ] **Step 3:** `undo.js` schreiben.
- [ ] **Step 4:** → PASS
